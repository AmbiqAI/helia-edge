---
title: Export and quantization
description: Convert a TensorFlow-backed Keras model to LiteRT, inspect predictions and save the model artifact.
---

heliaEDGE's LiteRT/TFLite converters prepare model artifacts for inference. Conversion uses TensorFlow even when another part of your project uses the Torch backend. Run it in the appropriate environment and check the operators and input contract required by your deployment target.

## Install the conversion capability

From the source checkout used by the installation guide:

```sh
uv sync --python 3.12 --extra litert
```

Use a TensorFlow-backed Keras model. See [Backend support](/helia-edge/getting-started/backends/) for the supported Python environment. The Torch converter namespace is a placeholder and does not provide a working export path in this source version.

## Convert and inspect

With a trained `model` and a NumPy array `representative_x` matching its input shape:

```python
from helia_edge.converters.litert import LiteRTKerasConverter, QuantizationType

converter = LiteRTKerasConverter(model)
content = converter.convert(
    representative_x,
    quantization=QuantizationType.INT8,
)
converted_predictions = converter.predict(representative_x)
converter.export("model.tflite")
```

Choose representative inputs from the distribution the model will encounter. INT8 and INT16X8 conversion require representative data. Compare converted predictions against the original model and evaluate task quality on held-out data before deployment.

<details>
<summary>Compare precision options and target requirements</summary>

| Format | Use |
|---|---|
| FP32 | Establish a floating-point conversion baseline. |
| FP16 | Store weights as float16; they are dequantized at runtime and compute stays FP32. |
| FP16_NATIVE | Emit a float16 graph: inputs, weights, activations and outputs are float16. Needs a runtime with float16 kernels for every operator; `tf.lite.Interpreter` cannot run it, and `predict()` rejects it. |
| INT8 | Quantize with representative data and validate the resulting input/output types. |
| INT16X8 | Request the converter's 16-bit activation / 8-bit weight path where supported by the model and target. |

A converter accepting a precision option does not establish that every operator, runtime or hardware target supports it. Inspect the exported artifact and validate it with the intended runtime.

</details>

<details>
<summary>Save bytes or a C header</summary>

`export()` writes the converted content. `export_header()` emits a C byte array when your firmware integration needs one. These methods are inherited from [TfLiteKerasConverter](/helia-edge/reference/api/helia_edge/converters/tflite/converter/); [LiteRTKerasConverter](/helia-edge/reference/api/helia_edge/converters/litert/converter/) supplies LiteRT runtime prediction.

Keep the original trained model, calibration selection, conversion settings and validation results with the exported file. Firmware integration and on-device measurements are separate steps from host conversion.

</details>

## Hand off to an Ambiq deployment

The exported model is one part of the deployment. Select the inference runtime and check its operator and precision support before integrating it into firmware. Training backend support does not imply that every model can run on every target.

| Keep with the model | Why the deployment needs it |
|---|---|
| Input shape, layout and dtype | Defines how firmware supplies each inference window. |
| Preprocessing parameters | Keeps scaling, filtering and feature extraction consistent with training. |
| Output names and interpretation | Defines class order, thresholds or reconstruction units. |
| Calibration and quantization settings | Explains how the converted artifact was produced. |
| Representative inputs and expected outputs | Enables comparison between host inference and the deployed runtime. |
| Model and source revisions | Identifies the exact artifact being evaluated. |

Validate task quality after conversion, then measure latency and memory with the model on your intended Ambiq board. Host conversion and operation counts do not establish device performance. For streaming models, include the state shapes, initialization and update order described in the model's guide.
